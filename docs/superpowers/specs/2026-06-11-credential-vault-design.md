# LazyTerm 凭据保险库设计

## 目标

在不依赖 Credential Manager、Keychain 或云服务的前提下，让 SSH、RDP、VNC 凭据以密文随 Git 配置和 JSON 备份迁移，同时保持默认使用无额外操作。

## 模式

- 默认模式：使用应用内置固定材料派生 AES-256-GCM 密钥。它用于避免配置文件直接暴露明文，不承诺抵御针对性逆向。
- 主密码模式：使用 PBKDF2-SHA-256 从用户主密码和随机盐派生 AES-256-GCM 密钥。每次启动首次使用前解锁一次，密钥只驻留内存。

## 存储

`lazy-term-credentials` 保存版本化保险库，包含模式、KDF 参数、校验密文、凭据元数据和敏感字段密文。用户名、名称、私钥路径和备注作为可迁移元数据保存；密码、私钥正文和私钥口令始终位于 AES-GCM 密文中。

每个凭据使用独立随机 IV。主密码、派生密钥和解密后的敏感字段不写入 localStorage、Git 文件或 JSON 备份。

## 生命周期

应用启动时读取保险库。默认模式自动解锁；主密码模式显示阻塞式解锁窗口。凭据解密后仅保存在 Zustand 运行时状态。保存或编辑凭据时先加密，再原子更新 localStorage。

旧版明文 `lazy-term-credentials` 在首次启动时自动转换为默认模式密文。SSH、RDP、VNC 会话配置中原有的密码、私钥正文和私钥口令也会在保险库解锁后自动迁移为独立凭据，会话配置只保留 `credentialId`。只有密文写入成功后，明文字段才从持久化数据中消失。

## 迁移

Git 同步增加 `lazy-term-credentials`。JSON 备份直接携带完整密文保险库和仅引用 `credentialId` 的会话配置。默认模式在新设备上无需操作；主密码模式在新设备首次启动时输入相同主密码。

## 错误处理

解锁失败不修改保险库。加密或持久化失败时不更新运行时凭据列表。忘记主密码时允许清空凭据保险库，但连接配置和其他应用数据不受影响。

## 验证

不创建或运行测试代码。使用 TypeScript `tsc --noEmit`、Rust `cargo check` 和代码审查验证。
