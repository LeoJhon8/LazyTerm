# 统一连接遮罩设计

## 目标

统一 SSH、VNC、FreeRDP 和 MSTSCAX 的连接中、认证中、重连中、失败和断开显示。所有协议共享相同的视觉层级与交互规则，同时保留图形协议首帧同步和 MSTSCAX 原生窗口避让所需的专用过渡处理。

## 视觉规则

采用分阶段混合方案：

- `connecting`、`authenticating`、`reconnecting` 使用居中的轻量遮罩，显示状态、协议和目标地址，不展示大段配置。
- `failed`、`disconnected` 使用完整诊断卡片，显示摘要、目标信息、可折叠技术详情和重新连接按钮。
- `connected`、`idle`、`closing` 不显示连接状态遮罩。
- 轻量遮罩和诊断卡片均覆盖当前会话内容，但保留最后终端输出或最后远程桌面画面作为背景。

## 组件边界

新增统一的 `ConnectionStatusOverlay`，输入为 `SessionConnectionStatus`、协议标签、目标地址、可选说明和重连回调。组件内部负责把连接阶段映射为轻量遮罩、诊断卡片或隐藏状态。

现有 `TransitionMask` 调整为语义明确的 `SessionTransitionMask`，只处理不属于连接生命周期的短暂视觉过渡：

- VNC 和 FreeRDP 首帧解码或画面同步。
- FreeRDP 和 MSTSCAX 会话尺寸调整。
- MSTSCAX 打开 Web 菜单或对话框时隐藏原生窗口。

协议视图不再自行判断连接遮罩的布局和颜色，只负责提供协议特有文案与目标信息。MSTSCAX 仍保留原生窗口显示、隐藏和挂载逻辑，但其连接状态显示使用统一组件。

## 状态映射

| 状态 | 显示方式 | 默认文案 |
| --- | --- | --- |
| `connecting` | 轻量遮罩 | 正在建立连接... |
| `authenticating` | 轻量遮罩 | 正在验证凭据... |
| `reconnecting` | 轻量遮罩 | 正在重新连接... |
| `failed` | 诊断卡片 | 连接失败 |
| `disconnected` | 诊断卡片 | 连接断开 |
| `idle` / `connected` / `closing` | 隐藏 | 无 |

图形协议已经进入 `connected` 但首帧尚未显示时，不伪造新的连接状态，而是显示 `SessionTransitionMask`，文案分别为“正在同步 VNC 画面...”或“正在同步 Windows 远程桌面画面...”。

## 协议适配

- SSH：替换顶部胶囊提示，连接中使用统一轻量遮罩，失败和断开使用诊断卡片。
- VNC：连接状态交给统一组件；首帧等待和尺寸变化继续使用过渡遮罩。
- FreeRDP：与 VNC 使用相同规则，首帧和尺寸调整属于过渡遮罩。
- MSTSCAX：移除本地 `overlayMode` 对连接状态 UI 的重复决策，优先使用 session 的统一连接状态；原生 host 状态仅用于控制窗口挂载、可见性和过渡遮罩。

## 交互与层级

- 连接中遮罩不可交互，避免阻塞连接完成后的自动切换。
- 失败和断开卡片允许点击“重新连接”和展开技术详情。
- 连接状态遮罩高于会话内容，低于应用级菜单和对话框。
- `SessionTransitionMask` 高于原生或 Canvas 会话画面；MSTSCAX 显示该遮罩时必须同步隐藏原生窗口。
- 同一时刻只显示一种主遮罩。失败或断开优先于任何过渡遮罩。

## 验证

遵循项目规则，不创建或运行测试代码，也不执行 build。使用 `tsc --noEmit`、代码审查和用户人工验证，重点检查四种协议的首次连接、认证、重连、失败、断开和图形首帧场景。
