# 仓库公开前检查清单

> **简体中文** | [English](../en/developer/public-release-checklist.md)

本文档只记录准备工作，不会修改 GitHub 仓库的可见性。将仓库切换为 Public 必须由维护者在完成全部检查后手动执行。

复选状态是仓库准备工作的历史记录。翻译、排版或普通文档更新不得改变完成状态；只有实际重新验证后才能勾选新项目。

## 许可证与发布

- [x] 项目许可证统一为 `GPL-3.0-or-later`。
- [x] `package.json`、`Cargo.toml` 和 README 中的许可证声明一致。
- [x] 安装包资源包含 `LICENSE` 和 `THIRD_PARTY_NOTICES.md`。
- [x] 已记录当前 FreeRDP、WinPR 和 OpenSSL DLL 的版本与 SHA-256。
- [x] 已对 `package-lock.json` 和 Cargo 依赖元数据执行 GPLv3 兼容性基线检查。
- [ ] 确认每个预编译 DLL 的准确下载地址、构建来源和对应源码标签，并在更新二进制时同步更新第三方声明。
- [ ] 根据最终安装包生成完整第三方清单，并复核需要随二进制提供的版权声明和许可证全文。

GPL 允许仓库保持私有用于内部开发，但向第三方分发 GPL 二进制时必须同时提供相应版本的完整对应源代码。仓库公开前，不要将采用新许可证构建的安装包发布到公开更新服务器。

## 身份与知识产权

- [ ] 确认所有提交均有权以 GPL-3.0-or-later 公开，不包含雇主、客户或其他项目的专有代码。
- [ ] 检查全部 Git 作者姓名和邮箱，决定保留历史、重写为 GitHub noreply 邮箱，或以干净快照建立公开仓库。
- [ ] 如需重写历史，先创建只读备份，并在独立克隆中演练；不要直接对唯一仓库强制推送。

## 敏感信息

- [x] 2026-08-03 使用 Gitleaks 8.30.1 完成基线全历史扫描，未发现泄露项。
- [ ] 在最终公开版本上再次运行 Gitleaks 全历史扫描：`gitleaks git . --redact=100`。
- [ ] 人工检查历史中的 `.env`、证书、私钥、Token、真实主机、用户名、日志和导出的连接配置。
- [ ] 对曾经进入 Git 历史的凭据先执行吊销或轮换；仅删除文件或改写历史不能使凭据重新安全。

## 安全与社区设置

- [x] 已添加 `SECURITY.md`、`CONTRIBUTING.md`、`SUPPORT.md`。
- [x] 已添加 Bug、Feature 和 Pull Request 模板。
- [ ] 在 GitHub 仓库设置中启用 Private Vulnerability Reporting。
- [ ] 确认 Issue 标签、仓库描述、Topics 和默认分支保护符合预期。
- [ ] 明确首个公开版本的支持范围，并准备已知问题列表。

## 发布完整性

- [ ] 为首个公开版本创建源代码 Tag，确保二进制与该 Tag 一一对应。
- [ ] 随安装包提供许可证、第三方声明、校验和与对应源代码地址。
- [ ] 检查 Windows 和 macOS 签名流程，不在仓库或构建日志中暴露签名凭据。
- [ ] 从无权限、未登录环境验证源码、Release、Issue 模板和安全报告入口均可访问。

## 切换可见性

- [ ] 再次确认默认分支和所有历史引用均已完成敏感信息检查。
- [ ] 由维护者手动将 GitHub 仓库切换为 Public。
- [ ] 公开后立即执行一次匿名克隆并检查仓库首页、许可证识别和发布下载链接。
